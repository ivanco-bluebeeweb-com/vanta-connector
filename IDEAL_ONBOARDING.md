# Vanta Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md` (портфельный стандарт, см. Middesk/Alloy/
Oracle HCM Connector). Целевой пользователь: Security/Compliance-инженер или GRC-менеджер
компании, проходящей SOC 2 / ISO 27001 / HIPAA сертификацию на Vanta.

## 1. Credential type
OAuth2 Client Credentials: Client ID + Client Secret (создаются в Vanta > Settings > API),
плюс необязательное поле base_url для нестандартных/сегрегированных инстансов.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` со ссылкой на Vanta Settings > API + короткое объяснение:
   "создайте API-приложение в Vanta и вставьте его Client ID/Secret — доступ будет ровно
   таким, какие scope вы дали этому приложению в самой Vanta".
2. **Форма подключения** — Client ID (текст) + Client Secret (password) + необязательный
   base_url. Явно указано, что это НЕ ваш личный логин Vanta, а отдельное API-приложение.
3. **После успеха** — первым экраном сразу открывается компактная сводка
   `audit_compliance_posture`: сколько тестов failing, сколько рисков просрочено на
   ревью, сколько vendor-проверок просрочено — то есть самое ценное, ради чего человек
   вообще подключил compliance-инструмент, видно сразу, а не спрятано в меню.
4. **Ошибка scope (403)** — конкретное сообщение "у этого API-приложения в Vanta нет
   доступа к этому разделу — откройте Vanta Settings > API и добавьте нужный scope",
   а не общий 403.
5. **Множественные организации** — если у пользователя несколько Vanta org (например,
   агентство ведёт несколько клиентов), поддерживается несколько сохранённых подключений
   с явным label на каждое, как в Middesk/Alloy.
